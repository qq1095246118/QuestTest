## 规则依据

本次通过已登录浏览器核对了用户提供的
[因子库 4.0 技术方案](https://jjp1ynw9z1yy.jp.larksuite.com/wiki/Vr1WwD2YJi7INNkNcQjjyWcmpLg)，
页面显示最后修改于 9 月 5 日。使用第 4.2、8、8.1～8.4 节，未将旧报告当成当前环境验收结果。

- 原链路 env-score-v1 对成功指标分别做环境准入，失败条件逐项保留；未成功指标的有效性、维度分数和置信度为空。
- TS/CS 任一维度有效即可参与合成；无效维度不占权重，剩余维度重新归一；两个维度都无效不能进入候选。
- 维度分数与置信度先分别加权，再相乘得到 routing score；最终分数保留 6 位，置信度保留 9 位。
- 最低分判断使用评分器输出的六位最终分数。原 route 重算检查同步此顺序，避免与新候选检查相反；精确舍入中点影响结果时仍阻断，不臆造中点规则。
- 文档允许原链路按因子增量发布；不能仅因 batch 仍 running 就判 active route 非法。v2 只持久化指标、不评分不发布，不套用 v1 分数要求。
- 文档明确具备资格不等于已经发布；接口 TopN 过滤不等于 Backend 发布是否保留全部候选的契约。

数据库读取同步修正：所有 metric 均保留结果 payload，不再只读取 routing_score 非空行；
保留字段未提供与显式 null 的区别、全部拒绝原因及 OOS 摘要。只去掉本轮不需要的逐折大数组和输入指纹。
旧离线窄投影替身仍兼容，但不由其缺字段重建出伪造的真实输入。

## 验证边界

前四组已实现正式业务断言，不表示真实环境已通过，也不表示当前自然数据恰好包含所有边界。
每次执行必须区分已检查失败、已检查通过、缺少自然样本和缺少规则；同一 Case 中已确认失败优先。

1. 全部发布入选规则仍待确认：Backend 发布后是否必须包括全部具备资格的因子，是否存在 TopN、停用过滤、逐因子确认或其他限制。当前输出明确的候选差集；不借 route 表或 summary 自证完整，也不把差集直接定性为漏发布 Bug。
2. requested OOS 折数与最少有效折配置不一致时，文档未明确具体解析式。已解析证据与冻结配置一致的记录可检查，不一致的组合不自行采用 min/max。
3. 六位/九位精度已明确，但精确舍入中点策略未明确。普通舍入分支可检查，中点策略影响结果时阻断。
4. 未知评分版本、未记录的输入或额外未定义拒绝码，不按 v1 规则硬判，也不计作通过。
5. 缺少某分区、身份类型、自然等号/null/回退形态时列出缺口。coverage 与方向一致率的越界值不属于合法最终结果，不再要求真实环境构造越界样本来满足本轮覆盖。
6. MCP 环境指标和标签端点没有 as_of 参数；指标绑定显式 batch，默认批次/标签读取核对前后发布指针。公式端点支持 as_of，推荐链按其真实接口参数调用，不虚构查询能力。
7. 多分区矩阵使用每个形态的真实代表，不声称遍历全部因子。空样本按最新状态保守选择可查询目录实体，历史有效但现已删除的实体不能作为正向空结果样本。
