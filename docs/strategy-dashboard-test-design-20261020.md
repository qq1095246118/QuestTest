## 每批生成的工作单位

按一个业务模块或约 15～25 条正式用例分批展开。每批先列出输入的需求编号和检查点编号，再写用例，最后更新映射和未完成列表。续写从文件中的编号继续，不依赖聊天摘要记忆已写内容。

每条正式用例保留：需求来源、优先级、身份与统计范围、前置状态、原始输入和事件时间线、操作步骤、独立公式与预期数值/状态、源数据/发布/API/UI 的检查点、执行方式、清理方式及证据。共用前置和步骤可以引用；各分支的数据、预期和结果分别记录。

“低于、等于、高于阈值”需要三条明确的子场景；“重复、并发、超时后成功、超时后失败”分别留编号。一个“大场景均正确”的断言不替代这些分支。

## 覆盖核查

| 核查对象 | 完成条件 |
| --- | --- |
| 需求 | 每个本版条款、公式、页面字段和动作能找到对应检查点；未读出的图片细项显式登记核验任务。 |
| 检查点 | 每条有正式用例或明确“待展开”；多个参数不能只保留一个样本。 |
| 正式用例 | 有原始输入、操作及唯一预期；计算预期从原始事实独立得到。 |
| 执行入口 | 标明经过上游采集、计算、API、UI 中哪些层；注入结果后读取只记录其实际覆盖层。 |
| 旧资产 | 每个原有编号有去向；被替换的公式、旧流程、范围外场景留下迁移记录。 |
| 结果 | 原始证据、实际值、执行版本及状态齐全；跳过、样本缺口和环境阻断分别列示。 |

按需求设计、检查点展开、执行器接入、真实执行、业务通过分别统计。226 个旧主用例、38 个接入子场景、24 个展示子场景以及本轮检查点属于不同层级，不相加成“已覆盖用例数”。
