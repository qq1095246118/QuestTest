# 策略看板待补充结果级场景

本文件记录本轮执行后确认的真实覆盖缺口。它们暂不计入当前 175 条已设计用例，待策略看板接口、响应 Schema 和可控样本接入后，再迁移为可执行用例。已经覆盖的 M01～M25、主链路、分页、当前/历史/清算 Tab、账户/策略隔离、去重、基础资金收益、回撤、执行、分润、收款和清算场景不在这里重复。

## GAP-001 最近到账时间取值

- 前置：同一账单集合存在多笔收款，分别有登记时间、审核时间和实际到账时间；收款跨月。
- 步骤：查询账单集合、收款明细和总览“最近到账”字段；分别隐藏登记时间或审核时间，保留实际到账时间。
- 接口断言：最近到账时间等于同一账单集合中已确认收款的最大实际到账时间，不取登记时间或审核时间；没有已确认收款时返回 null/不可用。
- 页面断言：账单详情、总览和跨月汇总显示同一个时间；待审核凭证不参与最近到账时间。

## GAP-002 逾期状态的严格边界

- 前置：准备当前时间等于到期时间、晚于到期时间、尚未到期、应收已足额、仍有待收、存在待审核款和没有到期时间的样本。
- 步骤：逐组查询账单状态和逾期字段；对照应收、实收、待收及到期时间。
- 接口断言：只有当前时刻严格晚于已批准到期时间且待收大于 0 时才标记逾期；等于到期、足额到账、没有到期时间或待审核规则阻断时不能误标逾期。
- 页面断言：逾期标签、待收金额和到期时间一致，不把“待审核”直接显示成“逾期”。

## GAP-003 累计净值与清算周期净值曲线

- 前置：准备累计收益率、清算后展示收益率、清算点和有/无资金流两组完整时间序列。
- 步骤：查询累计曲线、清算周期曲线和净值卡；独立计算 `1 + M03` 与 `1 + M04`。
- 接口断言：累计净值按 `1 + G/D`；清算周期净值按 `1 + (G-Gclear)/(D+Gclear)`；两条曲线不混用清算基准。
- 页面断言：清算点只重置周期曲线，累计净值和真实净值曲线保留历史；有资金流时固定本金净值按已批准规则返回不可用或明确标识，不能伪造连续收益曲线。

## GAP-004 策略详情指标组合对账

- 前置：同一策略详情同时有净敞口、保证金使用率、Sortino、胜率、盈亏比和对应接口原值。
- 步骤：从策略详情接口读取所有指标；使用同一策略、同一窗口的基础结果手算；在页面逐项核对。
- 接口断言：每个指标都使用策略自身归属结果和同一时间窗口；缺分母或缺样本时只该指标不可用，不用账号总值或上一时点补齐。
- 页面断言：指标名称、单位、正负号、颜色和不可用状态逐项与接口对应；不能把策略详情指标显示成账户汇总指标。

## GAP-005 多币种费用和内部转账

- 前置：准备 USDT 交易、BNB 手续费、缺少汇率的费用事件，以及同一内部转账的转出和转入两端。
- 步骤：查询费用、资金流和净入金；分别提供期末汇率、事件时汇率和缺汇率样本；对照内部转账两端。
- 接口断言：费用折算使用已批准汇率时点；缺汇率不能静默按 0；内部转账在组合口径下只产生一次净 0 资金变化；外部出入金仍影响净入金。
- 页面断言：币种、原币金额、折算金额和不可用状态分别展示；不能把 BNB 费用或内部转账显示为交易收益。

## GAP-006 各页面默认窗口和日界线

- 前置：准备覆盖 29 日、30 个完整风险日、168 小时执行窗口和未闭合当日的完整事件序列，并在 UTC/UTC+8 日界线各放一条事件。
- 步骤：不设置筛选直接打开总览、执行、风险和详情；再设置相同日期范围重复查询；记录各接口窗口参数。
- 接口断言：各组件使用文档规定的默认窗口；执行、风险、收益不能互相套用窗口；未闭合日按规则排除或标记，不进入完整统计。
- 页面断言：页面标题、时间范围、曲线首尾点和卡片统计与请求窗口一致；不能出现控件显示一个范围、接口使用另一个范围。

## GAP-007 分润精确证据资格

- 前置：分别准备 USD 计价、非 USD 计价、G/D 不完整、来源水位过期、快照超过 2 分钟、未来时间戳和精确合格的结果。
- 步骤：逐组触发分润评估；查询资格状态、拒绝原因和账单列表；对照原始时间和币种字段。
- 接口断言：只有币种、G/D 完整、来源水位有效、非未来且快照时效合格的结果才能锁定分润；每个不合格条件返回明确原因，不生成有效账单。
- 页面断言：页面显示不可计费/待补证据及具体原因，不把陈旧或未来数据显示成正常达标。

## GAP-008 锁单后累计结果修订贯穿后继周期

- 前置：C1 已锁单，随后对同一累计结果做一次下修；C2 已按锁单边界开启并产生新收益。
- 步骤：读取修订前后的 C1、C2、Gbase、Gclear 和账单；分别查询当前累计、历史冻结和后继周期。
- 接口断言：修订按已批准规则进入核验/调整；不能同时从 C1 和 C2 双重扣减；C2 仍从锁单边界 Gbase 计算，旧应收不被静默改价。
- 页面断言：旧账单、调整状态、后继周期和当前收益的展示分开，不能把累计修订直接覆盖冻结金额。

## GAP-009 首次启用与首个合格快照边界

- 前置：启用前已有历史 G，启用后第一个合格精确快照在另一时间点到达；另准备启用前后均无合格快照的样本。
- 步骤：分别查询启用前、首个快照和首个后继周期；查看 Gbase 建立时间及计费资格。
- 接口断言：Gbase 只能由首个合格精确快照建立；启用前收益是否追溯按已批准规则处理，不能把历史 G 直接当作 Gclear 或自动计入新周期。
- 页面断言：首次基准、启用时间和可计费起点可区分；没有合格快照时显示待建立/不可计费，不显示伪造周期收益。

## GAP-010 运行、全登记、外部启用和归档的全集口径

- 前置：准备 running、stopped、外部 enabled 但本地未绑定、unknown、archived、绑定已结束的账号/策略关系。
- 步骤：分别查询运行中、全登记、外部启用和历史累计接口；对照策略数、账号数和金额集合。
- 接口断言：每个查询范围按定义返回完整集合；unknown、归档和外部启用对象不能被静默归入 stopped 或从历史全集删除。
- 页面断言：当前、历史和管理目录的范围标签清楚；同一对象不会因状态映射在多个互斥统计中重复计数。

## GAP-011 告警的来源鲜度和未来时间门禁

- 前置：准备数值达到收益/回撤/资金门槛，但来源水位过期、来源时间在未来、来源缺失和精确合格的四组样本。
- 步骤：逐组查询告警评估和通知记录；查看告警状态、来源时间和拒绝原因。
- 接口断言：陈旧、未来或缺来源的结果不能生成精确收益/分润告警，应返回 unknown/待补数据；只有合格来源才按数值阈值触发。
- 页面断言：告警卡显示数据不可用或待刷新，不把旧值当成当前达标，也不把数据鲜度问题伪装成业务未达标。

## GAP-012 账户基础字段共同时间水位

- 前置：准备 E、W、U、G、C、F 来自不同采集时点、计数器重置和部分字段延迟更新的结果。
- 步骤：查询账户基础字段及更新时间/来源水位；比较字段时点、余额关系和派生指标。
- 接口断言：不会把不同水位的字段拼成一套看似完整的结果；发现计数器重置或字段不一致时返回部分不可用或明确降级状态。
- 页面断言：更新时间、部分数据标识和派生指标状态与接口一致；不能用旧的 E 配新的 U/G/C/F 生成正常收益卡。

## 规则确认项

GAP-002、GAP-003、GAP-005、GAP-006、GAP-007、GAP-009 还依赖逾期起算点、资金流收益口径、币种折算、默认窗口、精确证据和首次启用追溯规则的最终确认。规则未确认前可以验证接口是否保留必要字段和状态，但不能把相反候选结果同时判为通过。
