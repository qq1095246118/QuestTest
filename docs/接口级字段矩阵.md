# 接口级字段矩阵

## 文档目的

本文档基于以下证据源，对 `docs/x.json` 中定义的 42 个接口做逐接口字段矩阵整理：

- OpenAPI 定义：`docs/x.json`
- 表级说明：`docs/数据库/数据库表及解释 .pdf`
- 仓库内可确认代码：`api_services/binance/*.py`、`core/dao.py`

本文档重点回答 4 个问题：

1. 每个接口接收哪些请求字段
2. 每个接口返回哪些核心响应字段
3. 每个接口依赖哪些数据库表或数据层
4. 每个接口的数据最终来自哪个上游接口

## 证据级别说明

| 级别 | 含义 |
|---|---|
| `代码确认` | 当前仓库中可找到代码、测试或 DAO 直接印证 |
| `文档确认` | `x.json` 或 PDF 中明确写出 |
| `推断` | 结合接口命名、表名、字段语义做高置信映射，但当前仓库无实现代码 |

## 共用字段模板

### 1. 通用响应信封

绝大多数接口都使用统一响应信封：

| 字段路径 | 含义 |
|---|---|
| `code` | 业务返回码 |
| `status` | 响应状态 |
| `message` | 响应说明 |
| `data` | 实际业务载荷 |

### 2. K 线行模板 `KlineRow`

适用于 legacy K 线、binance-full K 线、部分 factor-data 的 K 线结果行。

| 字段 | 含义 |
|---|---|
| `symbol` | 交易对 |
| `timestamp` / `open_time` | K 线开盘时间，毫秒 |
| `interval` | 周期，如 `1m`、`1h` |
| `open` | 开盘价 |
| `high` | 最高价 |
| `low` | 最低价 |
| `close` | 收盘价 |
| `volume` | 成交量 |
| `close_time` | 收盘时间 |
| `quote_volume` | 成交额 |
| `trade_count` / `trades` | 成交笔数 |
| `taker_buy_base_volume` | 主动买入基础资产量 |
| `taker_buy_quote_volume` | 主动买入计价资产量 |
| `quality_flag` | 清洗质量标记，仅 curated/clean 常见 |
| `repair_tag` | 修复标记，仅 curated/clean 常见 |

### 3. 时间边界模板 `TimeRangeLeaf`

| 字段 | 含义 |
|---|---|
| `time_field` | 时间字段名，如 `timestamp`、`funding_time` |
| `min_time_ms` | 最早时间 |
| `max_time_ms` | 最晚时间 |
| `has_data` | 是否有数据 |

### 4. 分页模板 `PaginationBlock`

| 字段 | 含义 |
|---|---|
| `limit` | 分页大小 |
| `offset` | 偏移量 |
| `include_total` | 是否计算总数 |
| `total` | 总行数，按需返回 |

### 5. 元数据模板 `RegistryRow`

| 字段 | 含义 |
|---|---|
| `symbol` | 合约 symbol |
| `status` | 交易状态 |
| `contract_type` | 合约类型 |
| `quote_asset` | 计价资产 |
| `margin_asset` | 保证金资产 |
| `is_enabled` | 是否启用 |
| `onboard_date_ms` | 上线时间 |

### 6. Funding 行模板 `FundingRow`

| 字段 | 含义 |
|---|---|
| `symbol` | 交易对 |
| `funding_rate` | 资金费率 |
| `funding_time` | 资金费率时间 |
| `mark_price` | 对应标记价格 |

### 7. 批量边界模板 `BatchBoundsRow`

| 字段 | 含义 |
|---|---|
| `symbol` | 标的 |
| `pair` | 连续/交割合约 pair |
| `interval` | 周期 |
| `min_time_ms` | 最早时间 |
| `max_time_ms` | 最晚时间 |
| `has_data` | 是否有数据 |

### 8. 因子查询模板 `FactorQueryPayload`

| 字段 | 含义 |
|---|---|
| `query` | 请求条件回显 |
| `rows` | 结果行数组 |
| `next_cursor` | 下一页游标 |
| `has_more` | 是否还有下一页 |
| `row_count_returned` | 当前返回行数 |
| `coverage` | 覆盖率信息 |
| `earliest_available_time_ms` | 最早可用时间 |

## 二、Coinglass 接口矩阵

说明：本组接口不应映射到 Binance 官方 API，而应映射到 Coinglass 上游或服务内聚合层。

### Coinglass V4 接入约束补充

| 项 | 官方说明 |
|---|---|
| 基础地址 | `https://open-api-v4.coinglass.com` |
| 鉴权方式 | 所有请求必须带 `CG-API-KEY` 请求头 |
| 限流反馈 | 响应头含 `API-KEY-MAX-LIMIT`、`API-KEY-USE-LIMIT` |
| 常见错误码 | `0/400/401/404/405/408/422/429/500` |
| 说明 | 频率限制取决于套餐；部分接口文档还标明缓存刷新频率，如 `10s`、`20s`、`1h` |

## 九、一致性结论

- `legacy K线`、`binance-full K线`、`funding`、`registry` 已能稳定映射到对应表族和 Binance 官方接口族。
- `factor-data` 是统一查询层，本身不直接面向 Binance，而是面向已落库的数据集。
- `coinglass` 相关接口与表不来自 Binance，必须单独对待，不能混入 Binance 溯源链。
- `volume-rank`、`top-gainers` 的物理表名在当前仓库中仍未出现，但其结果语义明显依赖内部汇总层和 Binance 历史行情。
- 当前仓库未包含 `x.json` 对应后端实现，因此本文档中的“依赖表”和“上游接口”以文档级映射为主。
