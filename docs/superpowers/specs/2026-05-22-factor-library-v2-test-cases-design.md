# 因子库 V2.0 测试方案与用例设计

## 目标

生成一份 Excel 工作簿，用于《因子库 V2.0》人工测试方案和测试用例评审。该工作簿面向产品、技术、测试三方对齐，重点明确测试范围、模块边界、业务规则、算法口径、执行级用例和待确认问题。

本次不生成 pytest 自动化用例，不修改 API 封装，不实现后端公式或业务代码。

## 资料来源

- `docs/因子库/因子库V2.0 需求文档.pdf`
- `docs/因子库/因子IC-IR分析体系说明.pdf`
- `docs/因子库/因子体系三层结构 -简版.pdf`
- `docs/因子库/因子体系三层结构_完整版.pdf`
- `docs/因子库/已实现子因子清单.pdf`
- 用户提供的墨刀原型链接
- QuestTest 现有资料：`docs/test_cases_factor_data.md`、`docs/接口级字段矩阵.md`，仅用于理解当前数据平台测试风格

当前会话未能稳定读取墨刀原型页面内容。因此 Excel 中必须保留 `原型状态` 字段。凡无法从原型确认的内容，标记为 `文档有但原型待确认`；若后续发现原型与需求不一致，标记为 `原型与文档不一致待确认`。

## 交付物

生成一个 Excel 工作簿，按页面或产品模块拆分 sheet。用户已选择按页面模块组织。

建议输出路径：

`artifacts/reports/factor_library_v2_test_cases.xlsx`

| `01_投研Agent` | 覆盖左侧导航、投研 Agent 入口、模块切换、页面基础展示。 |
| `02_团队` | 覆盖默认角色、团队成员列表、添加到团队、编辑、删除、字段展示。 |
| `03_创建人员` | 覆盖头像选择、人格、语气与风格、个人知识库、默认提示词、附件上传。 |
| `04_对话` | 覆盖多 Agent 对话协作、研究员介入、附件上传、相关因子、相关论文/研报/网页跳转。 |
| `05_调度` | 覆盖工作流顺序、团队成员拖拽、3-5 轮辩论、硬终止、软收敛、轮次上限终止。 |

| `08_工具` | 覆盖数据采集与多模态解析、Agent 协作编排、因子评价与过拟合检测、模型训练与优化工具。 |
| `09_数据仓库` | 覆盖金融文献与知识库数据、市场与另类数据、因子评价与基准数据。 |

| `12_母因子详情` | 覆盖 K 线窗口、最小窗口/滚动窗口/3 个滚动窗口/近 1 年/全样本、主流币/山寨币下钻、折线图、族内相关性。 |
| `13_子因子列表` | 覆盖时序/截面页面、IC/ICIR/t-stat/OOS、分层单调性、多空收益差、筛选、字段文案、新挖方式。 |
| `14_子因子详情` | 覆盖 K 线窗口、主流币/山寨币下钻、折线图、相似因子、公式和来源展示。 |

| `16_策略管理` | 覆盖策略指标与实时计算：收益、回撤、连续亏损、最大单笔亏损、Calmar、Sharpe、Sortino、胜率、盈亏比、盈利因子、R 方、空仓周期、回撤修复时间。 |
| `17_因子管理` | 需求文档只给出标题，作为评审 sheet 保留；新增、编辑、归档、版本、权限、审核流均标记待产品确认。 |
| `18_资金管理` | 覆盖合约保证金、已实现收益、未实现收益、累计手续费、累计返佣；交易所返佣接口差异标记为待确认。 |
| `99_待确认问题` | 汇总产品和技术评审需要确认的问题。 |

## 用例字段

每个用例 sheet 统一使用以下列：

`用例ID / 模块 / 子模块 / 优先级 / 用例类型 / 测试场景 / 前置条件 / 测试数据 / 操作步骤 / 预期结果 / 需求来源 / 原型状态 / 是否阻塞上线 / 待确认问题 / 备注`

字段规则：

- `需求来源`：填写 `需求文档`、`原型`、`因子体系文档`、`IC-IR说明`、`已实现子因子清单` 中的一个或多个。
- `原型状态`：填写 `原型已体现`、`文档有但原型待确认`、`原型与文档不一致待确认`。
- `是否阻塞上线`：P0 默认写 `是`；P1 根据风险选择 `是` 或 `否`；P2/P3 默认写 `否`。
- `待确认问题`：记录未明确事项，避免把推测写成固定预期。

## 优先级规则

| 优先级 | 定义 | 示例 |
|---|---|---|
| `P0` | 核心主链路，失败会导致因子库 V2.0 不可用。 | 创建/选择 Agent 团队、启动辩论、生成因子、因子工厂输出、母/子因子列表和详情基础展示、核心 IC/ICIR 展示。 |
| `P1` | 重要业务规则或核心异常，影响验收质量或数据可信度。 | 3-5 轮调度、终止机制、附件限制、IS/OOS、评分规则、相关性算法、主流币/山寨币下钻。 |
| `P2` | 增强交互、补充字段、图表展示或复杂筛选。 | 悬停展示全文、折线图默认筛选、族内相关性、相似因子、工具能力展示。 |
| `P3` | 远期或需求不清晰功能，先保留评审级用例。 | 因子管理细节、返佣接口差异、策略/资金深层计算边界。 |

P0/P1 写执行级用例，包含前置条件、测试数据、操作步骤和明确预期。P2/P3 可写评审级用例，避免 Excel 过度膨胀。

## 分模块覆盖口径

### 主链路：投研 Agent 到因子工厂

`01_投研Agent` 到 `06_因子工厂` 构成 P0/P1 主流程：

1. 进入投研 Agent 或 AI 实验室。
2. 配置或选择 Agent 团队。
3. 使用文本和可选附件发起对话或任务。
4. 启动多 Agent 辩论工作流。
5. 通过成功、失败、软收敛或轮次上限结束流程。
6. 生成因子，并在因子工厂中展示挖掘成果。

这些 sheet 应写详细执行级用例。

### 支撑配置与资源

`07_统计` 到 `10_设置` 覆盖支撑能力。关键配置和数据源选择按 P1 处理；纯展示类信息通常按 P2 处理。

### 因子库核心

`11_母因子列表` 到 `14_子因子详情` 覆盖因子库核心验收：

- 时序和截面页面切换。
- 筛选条件：新挖人员、新挖时间。
- 字段文案：`新建人员/新建时间` 改为 `新挖人员/新挖时间`。
- 新增字段：`新挖方式`，取值包括 `Agent`、`因子工厂`、`人工录入`。
- 时序指标：IC、ICIR、t-stat、OOS。
- 截面指标：IC、ICIR、分层单调性、多空收益差。
- 详情能力：不同 K 线窗口、主流币/山寨币下钻、折线图、相关性、相似因子、公式、来源。

列表和详情基础展示、跳转为 P0；指标口径和下钻为 P1；图表、相关性、相似因子等增强能力为 P2，除非产品定义为上线阻塞。

### 因子评价口径

`15_因子评价口径` 不使用“自动化测试”概念。这里的“自动化”是产品中的因子自动评价能力，表示系统自动计算因子有效性、稳定性和评分。

该 sheet 应覆盖：

- 时序因子和截面因子均可评价。
- 时序评价扩展到全部 55 个币对。
- 时序因子值基于过去 30 天日均 USDT 成交额加权。
- 时序相关性按 Pearson 计算。
- 截面相关性同时计算并入库 Pearson 和 Spearman。
- 截面因子自动打分按 Spearman。
- 滚动窗口用于计算 IC、ICIR 等指标。
- 默认持有期预测未来 1 根 K 线收益，即 `h = 1`。
- IC 和 ICIR 保留正负方向。
- IS/OOS 可采用固定 75%/25% 切分。
- IS 段必须能计算至少 3 个完整滚动 ICIR。
- OOS 段必须能计算至少 1 个完整滚动 ICIR。
- 正向指标按不可用阈值和较强阈值映射到 0-100。
- 多空收益差为负时评分为 0。
- 分层单调性比例保持在 0-1。

### 策略管理与资金管理

`16_策略管理` 覆盖需求文档明确命名的策略指标。若文档没有给出精确公式、数据源或刷新规则，预期结果中应写明“公式和数据源需产品/技术确认”，不得自行补公式。

`18_资金管理` 覆盖文档已命名字段。累计返佣因交易所接口、层级返佣和子账号汇总规则不清晰，默认按 P3 待确认处理，除非产品补充明确口径。

## 范围与非目标

本次范围：

- 基于《因子库 V2.0》全量需求生成人工测试方案和测试用例。
- P0/P1 提供执行级用例。
- P2/P3 提供评审级用例。
- 汇总产品和技术需要确认的问题。

本次不做：

- pytest 自动化实现。
- API 封装实现。
- 后端公式或业务逻辑实现。
- 猜测未定义的权限、状态、刷新频率或公式。
- 清理本地已有报告或其他未提交改动。

## 规模预估

预计用例数量：

- P0/P1 执行级用例：90-130 条。
- P2/P3 评审级用例：80-120 条。
- 总量：170-250 条。

最终数量可根据策略管理、因子管理、资金管理的未确认项多少调整。

## Excel 中必须包含的待确认问题

- 哪些原型页面是各模块的验收基准？
- 需求文档中的哪些内容属于本期上线范围，哪些属于后续范围？
- 研究员、评审员、管理员、技术人员等角色权限如何定义？
- 附件上传支持哪些文件类型、大小和安全校验？
- 因子入库、编辑、归档、版本管理、审核流的精确流程是什么？
- 统计、策略指标、资金指标的刷新频率是什么？
- 策略指标的权威公式是什么？
- 策略实时计算使用哪些数据源？
- 不同交易所返佣接口缺失或差异如何处理？
- 因子评价阈值哪些由产品配置，哪些由月度标准制定？
- 哪些页面只在原型中出现但需求文档未描述，或只在需求文档中出现但原型未体现？
