# 策略看板剩余跨层与流程补充用例

本文件只补充前四个设计文件没有覆盖的跨层一致性和生命周期边界。它们不是新的
公式数学场景，也不替代已有 `CALC` 参数化矩阵；每条用例都要求从真实来源或业务
动作开始，最后核对接口和页面结果。当前状态是未接入对应真实适配器，不把契约检查
或已有静态夹具通过算作业务通过。

### DATA-129 来源撤回/删除按墓碑传播且不继续计入

- 优先级：P0
- 前置/数据：一条已发布事实同时出现在目录、权益曲线、策略贡献和账单归因中；来源随后发出撤回/删除墓碑，另有未受影响事实。
- 步骤：记录撤回前各接口结果；提交墓碑并刷新；分别查询当前结果、历史结果、贡献、账单和审计 lineage。
- 期望：撤回事实不再进入当前可计算集合，受影响派生结果进入明确的修订/不可用状态并保留来源引用；未受影响事实不被删除或重复；历史账单不能被静默改成另一条事实。
- 自动化状态：`LIVE_ADAPTER_REQUIRED`，缺来源撤回事件和派生结果修订查询入口。

### DATA-130 采集批次取消或回滚必须原子可见

- 优先级：P0
- 前置/数据：批次包含账户 A、B 两组事实；A 已写入、B 写入失败，随后批次进入取消或回滚终态。
- 步骤：在写入中、取消前、取消后分别读取目录、汇总、曲线、贡献和批次状态；再发起同批次重试。
- 期望：取消或回滚中的批次不能以 `complete` 对外可见；A 的半批结果不能被当作完整汇总；回滚后旧批次不再参与正常查询，重试生成新批次且不重复 A 的事实。
- 自动化状态：`LIVE_ADAPTER_REQUIRED`，缺批次取消/回滚和原子可见性入口。

### DATA-131 首次同步未完成时明确 partial，完成后全页面读穿

- 优先级：P0
- 前置/数据：首次同步只有目录和资金来源完成，执行、持仓或历史来源仍在进行；随后所有来源完成同一代次。
- 步骤：分别在同步进行中和完成后打开总览、策略详情、账号详情及各 Tab；记录区块状态、generation 和数值。
- 期望：同步进行中只展示已完成区块，其余返回 `partial`/`refreshing`/不可用原因，不以 0 或空集合伪装；完成后所有区块切换到同一代次，旧的 partial 标识和占位值被清除。
- 自动化状态：`LIVE_ADAPTER_REQUIRED`，缺首次同步状态和跨页面读穿适配器。

### DATA-132 绑定并发变更保持唯一有效关系与历史边界

- 优先级：P0
- 前置/数据：同一账户和策略在两个会话同时执行解绑、重新绑定或更换负责人，操作时间相邻且使用不同请求版本。
- 步骤：并发提交两个关系变更；查询当前绑定、历史绑定区间、策略/账号目录及收益归属；重复提交获胜请求。
- 期望：同一有效时间点最多一条有效关系；只有一个请求成为业务获胜者，另一个返回冲突/过期版本；历史收益仍按其生效区间归属，重放获胜请求不生成重复绑定或收益。
- 自动化状态：`DESIGNED_NOT_CONNECTED`，缺关系变更动作入口和并发版本 fixture。

### FLOW-144 启停动作超时先查终态，重试不重复副作用

- 优先级：P0
- 前置/数据：停止或重启请求已发送但客户端超时；服务端可能已完成、仍处理中或未执行三种终态。
- 步骤：制造请求响应超时；按请求 ID查询动作状态；分别对已完成、处理中、未执行状态重试原动作；再读取目录、计费周期和历史归属。
- 期望：客户端超时不能直接判定失败或重复执行；已完成只返回原结果，处理中继续等待，未执行才允许一次重试；最终状态、代次和计费边界只推进一次。
- 自动化状态：`DESIGNED_NOT_CONNECTED`，缺启停动作状态查询和可控超时注入入口。

### FLOW-145 锁单评估与提交之间源代次变化必须重验

- 优先级：P0
- 前置/数据：评估时使用合格源快照 `g1` 且达到分润门槛；提交锁单前同一账户发布 `g2`，收益或证据状态发生变化。
- 步骤：保存评估返回的快照和门禁结果；推进源代次；提交原评估结果并查询账单、锁定基准和拒绝原因。
- 期望：提交必须绑定并重新校验评估快照；`g2` 不再合格时拒绝或要求重新评估，不得按旧结果生成账单；若产品允许锁定旧快照，账单必须明确引用 `g1` 且不重复计费。
- 自动化状态：`DESIGNED_NOT_CONNECTED`，缺锁单评估/提交动作及代次绑定接口。

### FLOW-146 同周期不同幂等键重复触发仍只产生一个业务结果

- 优先级：P0
- 前置/数据：同一账户同一计费周期已经达到门槛；两个会话使用不同幂等键并发发起锁单、收款确认或清算。
- 步骤：并发提交两组动作；查询账单、计费周期、资金流水和后继周期；再分别重放两个请求。
- 期望：业务唯一键按账户与周期约束，而不是只按幂等键约束；只有一个账单、后继周期和资金动作，第二请求返回冲突或原业务结果；重放不新增事实、不重复扣款。
- 自动化状态：`LIVE_ADAPTER_REQUIRED`，缺锁单、收款确认、清算动作和业务唯一键并发 fixture。

### FLOW-147 停用/解绑与分润动作并发保持状态机一致

- 优先级：P0
- 前置/数据：同一账户的账单已锁定或收款确认处理中，同时提交停止、解绑或重新绑定与确认收款/清算动作。
- 步骤：并发提交关系和分润动作；查询当前关系、账单、收款、清算、后继周期及页面状态；重复提交最终获胜请求。
- 期望：停止或解绑不删除既有账单和已确认收款；动作要么按状态机明确拒绝，要么绑定同一冻结快照完成；不能出现半清算、重复后继周期或跨账户归属，重放不改变最终状态。
- 自动化状态：`LIVE_ADAPTER_REQUIRED`，缺策略关系和分润动作的并发执行入口。
