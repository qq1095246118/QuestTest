# 账户详情初步用例：资金金额、账户收益与风险

日期：2026-10-20。状态：设计完成/待执行；存在明确待口径绑定项，见末尾。页面字段依据父任务实际读取的账户详情2999核心16卡；本文件负责其中13卡，当前仓位、胜率、盈亏比由交易明细分册设计。

本文件和同名JSON保存逐条独立用例；不减少既有264检查点。这里只设计、不写2999或其他业务账户、不执行本轮接口业务动作。金额和比率预期来自原始事实独立复算，未将本地Decimal算例核验计为服务测试通过。

## 字段与计算边界

| 页面真实标签 | API指标候选代码（执行前与当前响应绑定） | 本稿判定基线 |
| --- | --- | --- |
| 保证金（USDT） | margin_equity | 对应真实源金额，不与钱包/持仓保证金交换。 |
| 未实现盈亏（USDT） | unrealized_pnl | 对应真实源金额；不是已实现收益率分子。 |
| 已实现盈亏（USDT） | realized_pnl_gross | 账户从首笔量化订单起的全历史事实；切策略不清空。 |
| 总收益率 | cumulative_return | r=账户全历史已实现G/最新完整本金D；D含初始本金与确认实际净流入；D>0。 |
| 年化收益率 | annualized_return | 满7天后r/d×365；不足7天不可用；历史点各按当时资格。 |
| 实时回撤 | current_drawdown | 产品NAV=1+r；(截至当时高点NAV-当前NAV)/高点NAV；详情正数。 |
| 最大回撤 | max_drawdown | 同范围逐分钟实时回撤最大值，先高后低；日展示保留日内谷值。 |
| 总手续费（USDT） | commission_expense | 沿用批准正支出语义，来源归一化要留证；不为r再次扣除。 |
| 累计资费（USDT） | funding_pnl | USDT金额，收到为正、付出为负；不能合计费率。 |
| 波动率（标准差） | volatility | 合格闭合日收益样本标准差n-1；卡片按技术的年化σ日×√365；曲线频率按响应绑定。 |
| 夏普比率 | sharpe_ratio | μ=本页r/本页有效天数；σ围绕日样本算术均值；日=(μ-rf日)/σ日；卡片年化乘√365。 |
| 索提诺比率 | sortino_ratio | MAR=0，下行偏差=√(Σmin(日收益,0)²/全部有效日数)；分子μ同上；卡片年化乘√365。 |
| 卡玛比率 | calmar_ratio | 本页同范围简单年化/分钟产品NAV最大回撤；年化缺失或回撤0不可用。 |

## 来源及公共执行流程

| 源路径代码 | 入口与实际消费 | 验证边界 |
| --- | --- | --- |
| FIN | quant_accounts/profiles映射；实际NT/Prometheus金额输入，按当前分支进入fact_performance_sample/fact_nav_sample或采集源→quant_collection_batches/quant_account_snapshots→发布→N01/N02。 | 只有真正被选中的输入源可造数；表名不证明消费。直接写采集后快照只计该层后续覆盖。 |
| PERF | 合法本金、G及资金事件；fact_performance_sample/fact_nav_sample实际输入字段，适用时exchange_account_cash_flows；经quant_segmented_nt_facts/generations和发布读取。 | G为r的输入但可已是成交聚合输出；不投递成交时不宣称验证了逐笔成交到G。 |
| TIME | 真实首单fact_order/fact_fill、运行/切换account_strategy_assignment/migration及对应绩效输入。 | 账户从首单保留全历史；不把策略分段本金和套到账户，不自行把策略运行并集规则套到账户。 |
| FEE | fact_fill、fact_funding_fee及实际累计费用输入；经实际消费及发布。 | 成交费归类/符号/累计重置分别留证；不是只写最终费用合计。 |
| RISK | 原始G/D分钟序列→真实分钟产品NAV/闭合日风险计算→generations/curve_points→N01/N02。 | 不向NAV、回撤、波动率等结果字段填答案；源表若有同名结果列，确认本次命中重算分支。 |
| RATE | 真实/受控利率配置和FRED/财政部依赖入口，加RISK输入。 | 利率未声明专门事实表，不臆造表或重算端点；故障和刷新不能只改已算夏普状态。 |
| META | collection_batches、generations、curve_points、read_views及Redis发布引用。 | 这些主要为输出/追踪；直接改它们只能验证读取/映射/缓存，不验证前面的公式。 |

P1=源事实准备→正式消费/发布→N01/N02同范围对账→页面核验/证据/按身份清理；P2在P1中增加分钟NAV与闭合日逐步计算；P3增加真实利率来源与刷新证据；P4验证新旧输入、冻结视图及发布隔离。JSON中每条用例已展开该流程文字，表格使用流程代码避免重复。数据库修改提交后再等待消费者；历史UPDATE的修订/重放入口需先证明，不能靠篡改checkpoint强行通过。

每次执行保存：源行ID与时间、账户映射、各自batch/source_generation/generation引用、实际公式版本、有效天数、入选日点、API原值、页面值。不同流水线generation数字不要求相等；snapshot_id是读取视图，不是采集代次。value=null+明确原因+页面—统一称“不可用”，不是擅自规定接口具体status枚举。
